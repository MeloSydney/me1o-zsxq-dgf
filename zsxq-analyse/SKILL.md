# 知识星球内容分析（全量分类浓缩 HTML）

读取 `zsxq-export` 导出的 raw Markdown 文件，将**全部抓取数据**互斥地归入三个专栏，逐篇浓缩，并生成一个可离线打开的自包含 HTML：

1. **🌟 星大派专栏**：星主发布且标题或正文以“星大派”开头的帖子，以及标题中含“直播总结”的帖子
2. **📝 星主普通专栏**：除星大派外的全部星主帖子，不论有无能量评分
3. **🙋 用户提问专栏**：raw 文件「用户提问」章节中的全部 `q&a` 帖子

HTML 默认显示处理后的浓缩内容。每篇消息底部必须提供独立的“查看原文”折叠入口，用户可按需展开或收起对应的完整 raw 原文；页面顶部不提供全局原文开关。

不执行 Top N 筛选，也不因无评分而丢弃帖子。最终必须满足：

```text
星大派数量 + 星主普通数量 + 用户提问数量 = raw 帖子总数
```

每篇 raw 帖子必须且只能出现在一个专栏中。

## 输入参数

`$ARGUMENTS` 支持：

| 格式 | 示例 | 含义 |
|------|------|------|
| 文件路径 | `zsxq_md/0520_大锅饭_raw_2026-05-18_2026-05-20.md` | 直接指定 raw 文件 |
| 日期范围 | `3d` / `7d` / `2026-05-01:2026-05-05` | 自动查找匹配的 raw 文件 |
| 无参数 | 留空 | 自动查找最新的一份 raw 文件 |

### 文件查找规则

- 日期范围：计算 `start_date` 和 `end_date`，在 `/Users/melo/doc-Dgf/zsxq_md/` 中查找 `*raw_{start_date}_{end_date}.md`
- 无参数：查找 `/Users/melo/doc-Dgf/zsxq_md/` 下最新的一份 `*raw*.md`
- 找不到时提示：**“未找到对应的原始数据文件，请先使用 /zsxq-export 导出数据”**

## 执行步骤

### 1. 完整读取并解析 raw 文件

解析以下内容：

- 星主帖子：标题通常为 `## ⭐ {评分或无}分 | {MM-DD HH:MM} | {标题}`
- 用户提问章节：以 `## 🙋 用户提问` 开始，每篇标题通常为 `### ❓ ⭐ {评分或无}分 | {MM-DD HH:MM} | {标题}`
- 每篇帖子的发布时间、评分、正文、标签、附件和评论
- 用户提问中的提问者、问题正文、回答者及回答正文
- 每篇帖子的完整原始 Markdown 片段，作为 HTML 中可选显示的 raw 原文

不得只解析有评分帖子，也不得忽略 `### ❓` 用户提问子项。为每篇帖子生成稳定且唯一的 `post_id`；优先使用 raw 中的原始 ID，没有 ID 时可使用“类型 + 发布时间 + 标题”的稳定组合。

### 2. 按优先级分类

严格按以下优先级分类，保证互斥且完整：

1. **用户提问专栏**
   - raw 中 `## 🙋 用户提问` 章节下的所有 `### ❓` 帖子
   - 即使回答正文以“星大派”开头，仍归为用户提问
2. **星大派专栏**
   - 在非 `q&a` 星主帖子中，满足以下任一条件：
     1. 标题或正文去除评分前缀、Markdown 加粗符号和空白后，以“星大派”开头
     2. 标题中包含“直播总结”，不要求以该词开头，不受评分影响
3. **星主普通专栏**
   - 其余所有非 `q&a` 星主帖子
   - 无评分帖子也必须保留

分类完成后执行覆盖校验：

- 统计 raw 总数 `J`
- 统计星大派 `M`、星主普通 `N`、用户提问 `Q`
- 验证 `M + N + Q = J`
- 根据 `post_id` 检查无重复、无遗漏
- 若不相等，重新解析并定位问题，不得静默生成不完整 HTML

### 3. 浓缩总结全部帖子

对三个专栏中的**每一篇帖子**进行浓缩，不设置 Top N，不按评分淘汰。

#### 通用总结原则

- 每篇用 **2-5 句话**概括核心观点、关键数据和结论
- 内容较长时按逻辑分成 1-3 个短段落
- 保留并用粗体标记关键数字、增速、价格、目标价、评级和核心结论
- 公司名称和股票代码必须完整保留并加粗，如 **协创数据**（**300857.SZ**）
- 不额外搜索公司主营业务，不添加原文没有的事实
- 删除免责声明、重复格式文本和无信息量内容
- 评论区仅保留有信息价值的补充、澄清或重要追问
- 原文若截断或缺失，必须明确标注，不得臆测补全

#### 用户提问总结规则

每篇用户提问必须同时覆盖：

- **问题要点**：提问者关心的标的、现象或决策问题
- **回答要点**：星主回答的判断、逻辑、条件和风险提示
- 若尚无回答，写明“截至导出时暂无回答”
- 若回答中包含评分，保留评分，但评分不参与筛选和排序

#### 不同内容类型的重点

| 类型 | 总结重点 |
|------|----------|
| 星大派每日热点 | 当日核心事件、关键数据、受益方向与风险 |
| 星大派锐评/特刊 | 核心观点、操作纪律、政策或行业逻辑 |
| 直播总结 | 直播核心观点、操作框架、重点标的与风险提示 |
| 研报精读 | 核心观点、关键数据、评级/目标价、利好公司 |
| 行业分析 | 核心判断、逻辑链、重点关注方向 |
| 普通观点 | 主要结论、操作框架、风险提示 |
| 用户提问 | 问题要点 + 回答要点 + 有价值的追问或补充 |

### 4. 专栏分隔与内部排序

- 三个大类必须使用三个独立 `<section>`，拥有清晰的标题、数量和视觉边界，不得把不同类别的卡片混排
- 专栏整体顺序固定为：星大派专栏 → 星主普通专栏 → 用户提问专栏
- **三个专栏内部全部只按发布时间降序排列（最新在前）**
- 能量评分仅作为帖子元信息展示，不再影响星主普通专栏排序
- 时间相同时保持 raw 中的原始相对顺序
- 无法解析发布时间的帖子放在所属专栏末尾，并在生成结果中标记“时间未知”，不得丢弃

### 5. 生成自包含 HTML

输出路径为 raw 文件名去除 `_raw_` 并将扩展名改为 `.html`：

- raw：`/Users/melo/doc-Dgf/zsxq_md/{MMDD}_大锅饭_raw_{start_date}_{end_date}.md`
- 分析：`/Users/melo/doc-Dgf/zsxq_md/{MMDD}_大锅饭_{start_date}_{end_date}.html`

HTML 必须：

- 使用 UTF-8，包含 `<!doctype html>` 和响应式 viewport
- CSS、JavaScript 全部内嵌，不依赖 CDN、外部字体或网络请求，可离线打开
- 默认显示浓缩总结；每篇 raw 原文入口默认折叠
- 不提供页面顶部或其他全局“显示原文 / 隐藏原文”按钮
- 每篇帖子的 raw 原文使用 `<details class="raw-block"><summary>查看原文</summary>...</details>`，支持逐篇独立展开/收起
- `<details>` 初始不得包含 `open` 属性，保证页面载入时原文默认折叠
- raw 原文必须 HTML 转义后写入，至少转义 `& < > " '`，不得把 raw 中的 HTML 或脚本直接执行
- raw 原文使用 `white-space: pre-wrap` 保留换行，正文过长时允许区块内部滚动
- 每篇帖子使用独立 `.post-card`，包含发布时间、标题、可选评分、浓缩总结和对应 raw 原文
- 页面提供三个专栏的页内导航锚点和顶部数量汇总
- 即使某类数量为 0，也保留对应 `<section>` 并显示“本期无此类帖子”

#### 必需的交互结构

可调整样式，但每篇帖子必须保留以下等价行为：

```html
<article class="post-card" data-post-id="{唯一ID}">
  <div class="summary">{处理后的浓缩内容}</div>
  <details class="raw-block">
    <summary>查看原文</summary>
    <pre>{经过 HTML 转义的完整 raw 帖子片段}</pre>
  </details>
</article>
```

```css
.raw-block pre { white-space: pre-wrap; overflow-wrap: anywhere; }
```

依靠原生 `<details>` 实现逐篇切换，不增加全局按钮或控制脚本。每个 `<details class="raw-block">` 初始不得包含 `open` 属性；不得使用 `display: none` 隐藏整个 `.raw-block`，确保每张卡片下方始终可见“查看原文”入口。

### 6. HTML 内容结构

```html
<header>
  <h1>大锅饭与小伙伴的进步空间</h1>
  <p>来源、导出时间、日期范围、三个专栏数量与合计</p>
  <nav>星大派专栏 / 星主普通专栏 / 用户提问专栏</nav>
</header>

<main>
  <section id="xingdapai" class="category category-xingda">...</section>
  <section id="host-posts" class="category category-host">...</section>
  <section id="questions" class="category category-question">...</section>
</main>
```

三个专栏必须使用以下稳定、有效的 ASCII `id`：

- `id="xingdapai"`
- `id="host-posts"`
- `id="questions"`

每个专栏标题下标明“按发帖时间降序排列”。

### 7. 标题规则

- 标题保持简洁，原则上不超过 15 个汉字
- 星大派帖子优先保留“星大派锐评 / 每日热点 / 特刊”等子栏目名
- 标题含“直播总结”的帖子保留直播日期或主题，且必须归入星大派专栏
- 研报和行业分析提炼核心主题
- 用户提问提炼问题核心，不使用“某某提问”作为标题
- 不得省略原文中的公司名称或股票代码

### 8. 最终验证与输出

写入后必须验证：

- 输出文件扩展名为 `.html`，存在且非空，包含 `<!doctype html>`
- `xingdapai`、`host-posts`、`questions` 三个专栏均存在且互相分隔
- `.post-card` 总数等于 `J`
- 每个 `post_id` 唯一，每个 raw 帖子在 HTML 中有且仅有一张卡片
- 每张卡片恰好包含一个浓缩区 `.summary` 和一个原文区 `.raw-block`
- `M + N + Q = J`
- 三个专栏均按发布时间降序；评分不影响排序
- 每篇用户提问同时包含问题要点和回答要点，或明确标注暂无回答
- 页面不存在全局原文切换按钮
- 每张卡片均有一个可见的“查看原文”入口，对应 `<details class="raw-block">` 且初始不含 `open` 属性
- raw 中的 `<script>`、HTML 标签等内容已转义，不会被浏览器执行
- 若有可用浏览器，打开本地 HTML 验证每篇“查看原文”可独立展开/收起且三类布局正确

## 注意事项

- 此 skill 依赖 `zsxq-export` 生成的 raw 文件，不直接访问浏览器或 API
- 所有 raw 帖子都必须进入分析结果，不执行 Top N 筛选
- 能量评分只作为展示信息，不用于删除或排序帖子
- 用户提问不得跳过或混入其他专栏
- 星大派帖子及标题含“直播总结”的帖子必须进入星大派专栏，不得重复出现
- HTML 中嵌入的是每篇帖子的原始片段副本，raw Markdown 文件本身保持只读、不修改
- 只生成 HTML 分析文件，不再生成 Markdown 分析文件
